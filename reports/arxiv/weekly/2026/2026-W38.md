# arXiv 论文周报 2026-W38

2026-W38 的连续信号是：Agent 可靠性要同时核验授权来源、历史状态、证据充分性和最终环境效果，单次通过、模型自报与局部证书都不能替代整条链路验收。相比 W37，本周更突出框架配置的模型依赖、跨出口隐私泄漏、自动演化对评测漏洞的继承，以及形式化规格与真实任务的偏离；汇总仅依据9月14—18日五份日报，重复收录不算独立证据，未补搜 arXiv。

## 本周趋势概览

### 授权检查向跨上下文、跨出口和共享资源推进

授权内的动作仍可能违背当前任务，局部出口拦截也可能把泄漏转移到别处。连续路线是把来源、核验状态、资源归属和接收者权限放到模型之外维护，并在实际写入或发送前强制检查。

依据：15日信息流控制将 CWL 泄漏率从52.2%降至0.5%，但授权披露成功率仅32.7%；17日 ASLEval 中邮件覆盖下降54.8个百分点，会话泄漏覆盖仍为100%。18日 ClashBench 默认成功抢占率44.5%，核验状态丢失实验又显示删除限定可显著提高批准概率；这些是不同压力测试，不能合并为部署风险率。

### 框架优劣取决于模型、任务和状态预算

Shell、计划、摘要和检索都不是固定收益组件，强模型上的简化方案可能让另一模型明显退化。比较开始转向同模型配对、组件拆解和协议变换，而不是直接把完整系统榜单归因于底模。

依据：14日私有框架对照未检出原生 SDK 的平均通过率优势，16日 SWE-bench Verified 前30名相邻29对均不显著。18日框架消融中，仅 bash 让550B模型成功率从65.8%升至69.4%，却让 Mistral 从68.6%降至45.4%；14、15日重复收录的 Bash 研究只算一项证据。

### 记忆评测从开关增益转向写入资格与实际使用

检索到内容、答对问题、报对来源和确实依赖证据是不同层次；历史反馈与评测时点还可能把答案信息带回系统。方法上反复出现写入门控、按状态补证据、按需回读原文和内容替换对照，但长期在线积累错误仍缺验证。

依据：14日历史回放审计中，未来记忆使 Recall@100 虚增2.62—5.24个百分点；视频记忆审计中，错误场景内容仍保留93%的收益。16日再巩固模块仅贡献约2点且使用答案相关预热，17日 MIRAGE 出现答案正确率47%而来源与答案共同正确率仅18%，18日 JustMem 则把扩大检索与回读原文分开调度。

### 执行与形式验证增强，但规格正确性成为共同瓶颈

真实回放、持久状态检查、符号等价和证明内核能发现普通测试漏掉的问题，却只保证被建模或被检查的部分。跨日工作都需要再核验需求、抽象语义、外部 API 和传递依赖，不能把“验证通过”直接升级成任务正确。

依据：15日 SAT 专用求解器逐次验证证书，16日 CADWorld 检查原生工程文件，17日 ProgramDistill 回放隐藏行为链。18日 LIDT 自动形式化在仅剩1个未完成证明时仍有114/283个目标声明未就绪，MAGS 的100个终端程序全部通过 Dafny却仅82个通过独立安全检查，张量程序检查又发现600个随机测试遗漏的问题。

### 裁判、探针和评分规则都需独立真值与反事实审计

高相关、高 AUROC 或可读出标签，不足以支持近距排名、因果解释或上线拦截。连续问题包括裁判家族偏好、生成规则奖励编造、内部信号对错字和分布变化敏感，以及格式信号被误解为技能信号。

依据：14日 GAUGE 整体排名相关ρ=0.94，近距候选排序分歧仍为31%；16日 ImpossibleRubrics 仅更换核验器就使同批答案失败率从33.3%变为75.6%或66.7%。17日家族裁判支持率差为3.4—8.4个百分点，18日梯度归因中异任务同格式平均对齐约0.4、同任务跨格式类别约0，均要求重新限定指标解释。

### 效率路线转向按需状态访问，但质量与总账常未闭合

KV 压缩、卸载扫描、异步投机和按需注意力共同减少历史读取或重复计算；可用收益取决于缓存位置、并发、生成长度和任务证据需求。局部算子加速、容量扩大和查询 token 减少仍不能互换为端到端降本。

依据：15日 Self-Indexing Attention 算子最高10.3倍，整模型解码吞吐仅1.23倍；16日 JustFit 跑完约21.3万位置，但冷预填充约48分钟。17日 ASPIRE 只测解码前向，18日 ODA 的保质结果与1.98倍计时来自不同配置，DeepSeek-V4.1-Flash 则尚缺压缩组件消融和固定负载服务实测。

## 高频主题归类

### 授权、工作流状态与真实效果

W37强调跨跳授权与事务提交，W38进一步暴露交接摘要、共享资源和多个可见出口之间的缺口。可信结构只能保证它实际绑定并强制执行的语义，审批文本、工具注解和模型计划都不能自行充当授权。

- 调用成功与工作流正确分开：逻辑操作ID、状态查询、暂存、依赖和补偿需要工具接口提供证据，15日MCP异常目录尚未做故障注入验证。
- 调用申请审批工具不等于获得审批；按工具名检查历史也不保证审批与执行针对同一对象，17日CaMeLoT仍存在这一语义缺口。
- 隐私按接收者和可见出口统计，安全按既有任务健康统计；只看最终回答、邮件或新任务完成都会遗漏副作用。
- 软护栏与强制边界分开：16日AgentGuard异常率从69.0%降至26.7%，但过度拒绝率19.3%，且没有修改工具权限。

### 记忆生命周期与证据充分性

跨五日的记忆工作同时研究写入、污染、检索、压缩、回读和删除，稳定问题是信息在状态转换后是否仍有合法来源、正确时间和足够细节。现有增益多来自固定数据上的局部机制，不能直接称终身学习或长期可靠性。

- 写入与调用分开验收：15日持久记忆投毒中，防御降低PDF注入率后，已污染记忆的跨会话攻击成功率仍达96.7%，且端到端分母未交代清楚。
- 记忆内容替换比开关消融更能识别作用；报对来源仍不是因果依赖，需要移除、替换和独立状态恢复对照。
- 证据组合不等于逐条相关：18日The Missing Complement在五条证据预算下完整覆盖率73.0%对61.4%，同源码token预算下却仅80.6%对80.0%。
- 删除审计开始深入检索执行：18日向量索引研究发现返回过滤仍读取已删向量，但轨迹哈希不能证明没有漏记，也不覆盖磁盘、日志和模型记忆。

### 评测分辨率、声明核验与协议鲁棒性

本周多日把总分拆成执行、来源、恢复、覆盖和报告忠实度，并检验小分差是否有统计支持。更细的指标有诊断价值，但模板相关性、同源裁判和选择性分母仍会让精细评测失真。

- 未检出差异不等于等效：私有框架比较、SWE-bench近邻排名和LoCoMo记忆对照均需保留区间与任务范围。
- 裁判稳定不等于准确：18日完工声明审计八次判断中91.1%标签一致，但没有人工准确率验证；一行即算触及文件还会漏掉阅读深度虚报。
- 换题之外还要换协议：17日Bad Genius真实基准最终只验证一个接口字段变换，搜索花费6.89亿token，不能宣称已消除通用捷径。
- 公平、幻觉与安全分数不能互换：高弃答率、平局率、格式正确和结果命中分别需要正常效用、任务真值及执行效果对照。

### 验证闭环与自动改进的可信反馈

代码、SQL、科研、规则生成和形式化反复采用执行反馈修复，进步在于冻结验收与独立重放。共同风险是优化器可以适应错误评分，验证器也可能只确认自建规格，必须隔离目标定义、候选生成和最终验收。

- 规格先冻结、证明后检查仍不够：MAGS终端独立安全检查只有82/100，机器人加入任务成功约束前为0/20完成。
- 执行结果比较要修正任务语义：17日DualSQL用REX处理重复行、列置换和ORDER BY，但当前数据库结果相同仍不证明SQL等价。
- 生成器与验证器同源、能看到生成轨迹或共享参考判据，会降低反馈独立性；错误样本筛选与额外搜索收益必须拆开。
- 训练反馈影响行为分布：18日观察监督提升部分pass@k，却使8B终端pass@1从12.3%降至11.0%，探索覆盖不能替代单次可靠性。

### 效率的状态账本与质量账本

本周系统路线比W37更集中于何时读取、保留和恢复历史状态，投机解码也开始利用请求差异及训练在线反馈。应同时报告真实服务路径、峰值内存边界和任务质量，不能用不同配置的最佳数字拼成收益。

- 省扫描不必省服务时间：17日Fathom真实128k预填充状态下，相对Double Sparsity快1.26倍、对SparQ持平，且另存索引。
- 容量突破不等于可用延迟：JustFit极限配置解码4.99 token/s；SSD MoE的2.9GiB是分配器峰值，不包含完整文件页及系统页缓存。
- 投机吞吐要区分同batch、最大可容纳batch、单请求及连续批处理，并核验随机采样分布与请求级尾延迟。
- 预处理与训练要计入回本：技能、本体、原文恢复、检索控制器、路由蒸馏和离线搜索的费用不能从在线token指标中消失。

### 内部信号与机制解释的边界

W37的探针有效性审计在本周扩展到错字、视觉语义、奖励投机、置信度和梯度归因。最稳的路线是冻结读出、加入标签与格式控制，再用独立干预检查行为变化，而不是从可分类直接跳到隐藏知识或真实意图。

- 16日Latent Undertow中平均3.33处编辑让低误报阈值下TPR从97.4%降至85.4%，AUC却只降0.55点；同分布修复不能外推未知域。
- 17日奖励投机探针与LLM监控取并集，把Kimi召回从41.1%升至80.2%、误报增加1点，但真值与基线同用模型裁判，且考虑后放弃也计阳性。
- 18日梯度归因支持格式主导平均对齐，不证明选数无效；安全稀疏检测的最佳结果依赖带标签校准，不能称纯无监督。
- HMM后验干预能定向改变预测，比单纯读出更强，但仍只覆盖小型合成隐状态任务，未识别自然语言中的完整贝叶斯更新机制。

- 验证器路线新增大型Lean交付、Rust密码验证和张量符号检查等较硬证据，同时更明确暴露规格失真、抽象遗漏与局部检查的边界；形式通过与用户意图正确仍需两层验收。

- 自动演化成为新的交叉问题：失败驱动造数、技能或本体优化有局部收益，污染基准也能把不安全策略固化到后续版本；这比单轮奖励投机更接近持久状态治理。

## 下周值得继续跟踪的问题

- 核验状态能否与授权声明、来源和对象ID结构化绑定，并在摘要、压缩、交接后由执行端独立校验，而非再交给模型解释一段JSON？
- 跨出口信息流控制能否在真实授权分享任务中同时保住完成率，覆盖改写、分片、多次输出拼接和未登记敏感信息，而不只拦精确原值？
- ClashBench的资源冲突能否用会话作用域、资源租约和独立准入规则解决，并同时报告安全完成、主动放弃和既有任务损伤？
- Shell与结构化工具在端点能力、权限、诊断、读写约束和总预算一致后还差多少；上下文策略的优势能否跨模型、多种子及真实长任务保持？
- 记忆方法在严格时间截断、无答案相关预热、反馈带噪且跨会话持续更新时是否仍有效；内容替换与原文回读分别贡献多少？
- 自动形式化能否把原始目标、传递依赖、API语义和编译映射纳入独立验收，并完整报告专家工时、失败修复与总计算成本？
- 污染基准在低污染比例、真实仓库和最终部署版本选择下能否持续改变Agent；定向去污染是否损伤原能力，能否先于写入长期规则发现？
- 裁判和探针在独立人工真值、未见模型家族、低误报阈值及自适应攻击下还能保留多少增益；近距排名是否应默认报告不可区分组？
- Reach/Solve交接能否从距成功两步扩展到多个检查点，保持原生预算与状态分布，并与观察监督、组合训练的收益归因结合？
- KV压缩、近似状态恢复、动态全局注意力和投机解码能否在同一学习策略、同一连续服务负载下同时保住质量、尾延迟、峰值内存与总成本，而不是分别报告最佳配置？
