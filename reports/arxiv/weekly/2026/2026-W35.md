# arXiv 论文周报 2026-W35

2026-W35 的连续主线是把模型外围系统当成主要研究对象：来源和授权要跨上下文重建保真，记忆与工具输出要保留血缘，harness、验证器和评测协议要单独审计。另一条持续信号是从最终得分转向执行证据、完整交付和物理后果；效率工作也不再只报压缩率或算子速度，而开始核对真实显存、通信、调用预算和端到端成本。

## 本周趋势概览

### 智能体安全边界移到执行层

多篇工作不再依赖模型识别恶意文本，而是追踪内容来源、用户授权、参数支持和数据去向，在工具真正执行前决定是否放行。连续出现的难点是正常外部数据必须影响动作，但不能借上下文重建、历史复用或参数补全扩大权限。

依据：Semantic Overlays、AgentFlow、StepGuard、SARA、SPA 和 When Context Gets Root 分别从残差标记、信息流策略、单步守卫、参数级授权、跨查询标签和角色重标切入。强结果仍受限于固定攻击模板、人工策略和合成工具链；SARA 总输入 token 达无防御的 1.91—2.21 倍，SPA 启用 IFC 后单轮效用从 53.0% 降到 29.0%。

### 记忆问题从容量转向使用、时效和隔离

本周反复出现的不是“记得更多”，而是能否在自然对话中用对记忆、把完整事件一起取回、识别已经失效的约束，并阻止恶意内容经写回和检索长期传播。摘要压缩、固定块检索和共享技能库都可能在边界处丢失安全语义。

依据：MemUse 的四个月部署显示增加长上下文或 RAG 容量没有带来额外满意度，且两阶段抽取后仍有 77% 的回复不引用检索到的细节；Reconstructing the Right Episode 用事件级检索改善多证据共存。Compaction Cliff、Stale Constraints 和 EVOMAL 又分别展示规则被反复压缩、验证预算错配和技能写回自投毒，但生产环境中的长期发生率仍未建立。

### 评测单位从答案变成执行证据

代码、科研、安全和 GUI 评测都在拆分“输出看起来正确”“实际完成任务”“过程有证据”“后果符合要求”。共同取舍是确定性验证更可审计，但任务合同、隐藏测试和规则评分器本身仍可能不完整或带主观性。

依据：SWE Refactor Bench 把迁移完成与行为保持分开后，520 次运行最终只有 28 次通过全部验证；FrontierChallenge 的最高平均分为 87.9，但最高严格通过率只有 20.6%。PLCBench 进一步把 PLC 读写与持续 30 秒的过程影响分开，240 轮中仅 75 轮达到最终目标；论文复现方向则用实现合同、语义要求和执行日志检查忠实度。

### Harness 成为独立优化对象

提示词、工具 schema、状态表示、完成检查、上下文裁剪和确定性技能被作为一套可搜索、可修改的软件系统，而不再被视为模型外的固定包装。同一模型换 harness 就可能显著改变成绩，但多数实验仍未把额外调用、搜索预算和各组件贡献拆干净。

依据：AutoSaddler、StarHarness、JIT-Agent 和 Same Model, Different Harness 都报告了跨任务或留出集增益；后者在 20,480 token 下把 SWE-bench Verified 完整解从 43 提到 72。代价是提示 token 从 37.8M 增至 80.7M、墙钟时间从 1.3 小时增至 4.6 小时，因此这是整体系统增益，不是等算力效率提升。

### 系统优化开始核对物理资源账本

KV 缓存、前缀复用、推测解码、机密计算和检索系统都在检查标称节省是否真的转化为显存、吞吐、通信或延迟收益。反复出现的结论是结构性复用有效，但低层存储布局、问题可见性、跨卡通信和额外评分计算会改变论文表面排名。

依据：Trust the Mass 查出部分 KV 淘汰结果依赖未真正释放显存或提前看到问题，且 ContourKV 的重构评分成本达到稠密 prefill 的 8.7—13.6 倍；Prefix Sliding 在 128K 长度把吞吐从 448 提到 5224 tok/s，但会无条件丢弃早期推理状态。Blackwell 机密计算实验则把默认软件栈的 35%—39% 损失定位到主机提交，修正后多卡推理损失约为 1.5%—3.6%。

### 闭环与物理后果进入智能体评测

机器人、工业控制和游戏工作不再满足于单步动作正确，而是检查推理延迟、动作块衔接、过程反馈和持续状态变化。连续信号是把慢速高层模型与高速控制器解耦，并通过中间状态或短执行长预测减少开环误差。

依据：Act with Intent 把局部行为目标写入 VLA 解码器，ARLI 用已承诺动作和推理中间观测补齐异步决策状态，GameWAM 采用预测 16 步、执行 8 步的闭环。PLCBench 和 PLC 硬件在环实验提醒，能调用或写入工具不等于产生持续物理影响；真实机器人和 PLC 结果仍集中在少量平台、任务与受控环境。

## 高频主题归类

### 来源、授权与数据流

本周最稳定的安全信号是：文本内容、消息角色和执行权限必须分开建模。模型侧拒答可以被包装、重放和历史复用绕过，真正有效的控制需要在上下文重建、参数绑定、工具执行和外部输出处保留来源与授权。

- 工具结果补全动态参数时，外部数据可以影响值，但不能扩大动作类型、目标、接收方或权限范围。
- 委派、定时任务、持久目标和子智能体加载会重标消息角色，来源元数据不能只保存在原会话。
- 单步守卫、信息流策略和参数级授权都存在误杀与额外调用成本，安全率必须和正常任务完成率一起报告。
- Office、网页、记忆和技能库都说明摄取与写回链路是安全边界，模型不是唯一受攻击组件。

### 长期记忆与上下文治理

记忆系统的瓶颈已从容量不足转为检索单位错误、生成阶段不用证据、约束过期和压缩丢失作用域。更长上下文只能缓解部分遗忘，不能替代事件化索引、时态更新、规则硬通道和写回隔离。

- Direct QA 高分不能预测自然对话中是否会主动、准确地使用旧信息。
- 固定文本块容易拆散共同生效的规则和例外，完整事件比局部语义相似片段更适合作为检索单位。
- 安全规则与普通事实一起反复摘要会出现压缩断崖，原样保留规则又带来预算和分类漏报问题。
- 共享技能和经验记忆若允许自动写回，会把错误、奖励投机或恶意模板固化并传播。

### 可执行评测与证据链

多类基准都在把最终答案拆成中间合同、执行轨迹、交付物和后果，目的不是增加评分维度，而是定位高分来自真正完成还是评测漏洞。连续出现的限制是规则评分器只覆盖作者事先想到的失败，LLM 裁判又会引入同源偏差。

- 代码迁移要同时验证实现替换和行为保持，科研任务要检查代码、数据、图表与报告彼此一致。
- 安全基准开始区分工具调用、真实利用、持续物理影响和无证据自述。
- 验证器本身需要 mutation testing、差分测试或人工抽查，返回通过不等于所有检查都实际执行。
- 单一平均分会掩盖关键字段遗漏、少数正确候选流失和严格交付失败。

### Harness、结构化接口与工作流搜索

Agent 外壳正从固定提示模板变成可演化的软件层，修改范围覆盖工具 schema、任务状态、上下文裁剪、完成检查和确定性操作。结构化状态和动作能显著缩短轨迹，但收益往往混入人工编码的领域知识、更多运行预算和更强验证器。

- 同模型换 harness 可产生两位数百分点差异，报告模型名称不足以复现实验。
- 工具接口、字段关系和确定性计算常比继续改提示词更能减少失败。
- 隐藏选择集和留出任务可减轻过拟合，但反复使用固定选择集仍会泄露反馈。
- 图、JSON DSL 和语义动作适合依赖明确的任务，动态试错和开放式环境仍需要自然语言或可恢复控制流。

### 资源真实性与低成本扩展

训练和服务优化的共同方向是利用模型内部或工作流中的非均匀性，而不是整体削减精度或上下文。可信结论越来越依赖物理字节、端到端延迟、通信、失败回退和额外模型调用的完整账本。

- KV 淘汰必须证明实际释放显存，逐头不等长缓存还需要对应内核和存储布局。
- 前缀复用、滑动窗口和语义分块能降低长序列成本，但会丢失早期状态或增加接口要求。
- 机密计算的主要损失可能来自主机提交和跨卡加密通信，而不是 GPU 算术本身。
- Muon 谱分配、消费级 GPU 预训练和训练数据课程展示了低成本路线，但单种子、总成本遗漏和特定硬件依赖仍普遍存在。

### 闭环控制与真实后果

机器人、游戏和工业控制研究共同强调动作不是终点，策略必须在推理延迟、旧动作承诺、环境反馈和长期误差累积下继续稳定。当前结果足以证明闭环设计重要，尚不足以证明跨平台、长任务和开放环境中的普遍可靠性。

- VLA 开始显式表示局部行为意图、二维接触区域和动作开始执行时的未来状态。
- 预测较长动作块但只执行前半段，可以兼顾生成效率与闭环修正。
- 能够调用控制接口或写入 PLC 不等于产生持续物理后果，评测需要独立过程轨迹。
- 真实机器人实验仍集中在少量桌面任务、单一平台和有限扰动，统计重复不足。
