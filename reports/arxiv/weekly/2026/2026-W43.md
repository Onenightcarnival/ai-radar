# arXiv 论文周报 2026-W43

2026-W43 的连续选题集中在 Agent 的证据与权限边界、长期记忆治理、过程验收，以及推理压缩的实际成本。10月19日、20日全部精读失败，只能提供题目级线索；实证判断均来自23日，不能把本周选题聚集解释为已验证的行业趋势。

## 本周趋势概览

### Agent 安全不能只看回答或拒答

反复出现的问题是：信息可读不等于结论可披露，最终状态正确不等于操作合规，拒答也可能同时泄密。可跟踪的方法路线是把授权、证据、动作及实际效果分开记录和验收。

依据：19日的 PRIME、20日的 SPIDES 与 RATION 仅提供证据核验和权限控制的题目线索；23日 Agent Mosaic 实测组合泄漏，AgentTriage 核对调用生命周期，TauIndianBankBench 发现只验最终状态会高估通过率6.5—12.0个百分点。

### 记忆评测从召回扩展到依赖与有效状态

源记录删除、摘要残留、状态过期和跨用户归属是不同故障，不能用问答准确率统一替代。原文检索加重排是必要的强基线，但不负责解决删除传播和状态治理。

依据：20日出现依赖绑定记忆与凭据归属题目；23日 AfterDeleteBench 检验衍生记录残留，Governance-State Corruption 单独扰动有效状态，Raw-RAG 则在七组主设置中六组领先所比记忆系统。后者主要测离线历史问答，不能据此否定治理机制。

### 代码 Agent 的反馈要落到可验证效果

执行、测试、证明和局部快照被用来约束搜索与纠错，而不再只评价诊断文本或最终分数。共同缺口是验证范围有限，以及缺少等总预算比较，尚不能把复杂反馈流程的成绩全部归因于新增机制。

依据：19日 Lean4AgenticRL、20日反例反馈与执行验证协同进化提供题目级连续线索；23日程序优化联合搜索实现和证明，RIPPLE 按修复效果分配信用，静态分析将审核反馈转成可复用规则。静态分析的关键消融未显著，程序优化也未证明原程序到 Lean 的迁移正确。

### 评测开始拆开指标背后的不同事件

内容出现、事实采信、动作意图、真实执行和有效防护不能共用一个“成功率”。本周多项工作直接检查评分器、参考规格、阈值和对照设计，显示部分高分来自验收口径而非能力提升。

依据：19日的空对照与噪声基线、20日的安全定义与验证器验收题目形成连续线索；23日 Data-Void 的31.0%包含仅列链接，ProductWebBench 区分需求完成和无回归，潜在危害监控研究在匹配误报率后重新比较探针与模型拒答。

### 推理压缩要区分精度、读取量与端到端收益

跨日反复出现预填充、KV、嵌入和解码优化，但节省 token、减少读取或压缩局部参数都不等于整机加速。23日的证据更适合按实际显存、完整延迟和独立校准后的质量分别判断。

依据：19日出现带宽瓶颈、冻结词表和 MoE 专家削减题目，20日出现 TokenGate 与并行解码；23日 MoEZip 缺端到端测量，OpenAttention 的约10倍仅来自排除选择等开销的单层配置，跨层嵌入量化则实测显存18.57→13.05 GB。

## 高频主题归类

### 证据、权限与动作效果分层验收

跨日报的共同问题是“看起来合理”与“有权且确实做对”之间存在缺口。23日的实证支持分层记录与核验，但尚无单一方案覆盖证据获取、组合授权、动作执行和最终影响。

- 可访问文档的组合结论仍可能越权；权限检查不能只停在检索入口。
- 回答、拒答、草稿与工具返回均不能替代动作效果证据；需保留调用标识和可核查事件。
- 缺证据时拒绝与补证后完成合法任务必须一起测，否则安全指标会奖励不作为。

### 记忆内容、衍生依赖与治理状态

记忆至少要分开评估检索质量、衍生信息删除和状态有效性。强Raw-RAG可以检验复杂写入是否值得，却不能替代删除传播或跨用户权限管理。

- 删除源记录后，摘要和组件组合仍可能恢复秘密；完整来源依赖是闭包删除的前提。
- 正确内容配上错误的删除、替换或过期状态，也会改变模型可见上下文。
- 能复述规则不等于正常执行时遵守规则；状态修复实验依赖已知正确状态，不能当作自主修复能力。

### 可验证反馈与信用分配

代码与实验Agent都在尝试把反馈从终局分数细化到局部修改及其效果。23日RIPPLE给出较完整机制消融，但静态分析、自主实验和多角色编排仍有预算或归因缺口。

- 诊断正确不等于修改有效，需比较修改前后测试快照并检查回归。
- 等价证明只覆盖其形式化对象，不能自动补齐迁移、规格和执行环境的正确性。
- 本地实验、候选筛选、评审与训练快照都应计入预算，正式提交次数减少不等于总成本下降。

### 质量保持与部署成本分开报告

压缩和早停路线已有明确的局部质量收益，但线上价值取决于统计收集、索引扫描、缓存复用及校准成本。真实显存测试比名义压缩比更接近部署判断，仍需跨硬件和真实负载复验。

- MoE压缩要同时保留上下文与专家路由稳定性，默认查询条件化方案可能损失缓存复用。
- 稀疏读取不一定释放KV显存，单层内核加速也不包含预填充、选择和更新开销。
- 早停的测试集前沿不是部署保证；按开发集选择策略后，测试准确率损失可能超过预设预算。

### 单日探索信号暂不升级为周趋势

功耗核验训练、Rowhammer经编译缓存放大降速、QKD形式化证明等工作值得单独读，但资料不足以支持各自的跨日连续趋势。不能仅因都涉及安全，就合并成统一技术路线。

- 功耗检测仍以合成轨迹为主，非训练周期负载会被误判，缺真实设施入口验证。
- Rowhammer工作给出了降速实验，但未报告物理翻转命中率和完整攻击成功次数。
- QKD证明连接了协议语义与有限密钥界，保证仍限于设备及信道假设，不是商用设备认证。

## 下周值得继续跟踪的问题

- 组合信息权限控制能否在真实检索与工具轨迹下同时降低泄漏、维持任务完成率，并将正常查询与对抗查询分别报告？
- 删除审计能否覆盖自主生成的压缩摘要、来源记录缺失和语义秘密，而不依赖逐字拼接或预先完整的依赖图？
- 记忆状态故障能否被在线检测和修复，而不是直接写回已知正确状态；与原文检索强基线比较时能否统一上下文和总成本？
- 代码Agent的证明、局部快照测试和反事实反馈，在相同总token、执行时间及人工投入下是否仍优于简单执行—修正循环？
- 安全探针在独立校准误报率、人工复核实际有害帮助后，能否稳定捕获模型自身未拒绝的风险，而不只是预测拒答？
- MoEZip与OpenAttention能否给出包含预填充、选择、统计更新和缓存复用的端到端吞吐、延迟与显存结果，并验证多轮Agent负载？
- 过程评测能否补上调用顺序、次数、回归判定稳定性和裁判误差，使任务完成率与真实合规、可靠性之间的差距可复核？
