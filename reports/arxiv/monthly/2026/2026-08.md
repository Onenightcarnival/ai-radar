# arXiv 论文月报 2026-08

2026-08 月报仅覆盖完整落在本月内的 2026-W35，因此以基线判断为主，不能据此确认环比升温。最集中的信号是研究重心从模型回答转向外围系统：来源与授权、记忆和上下文、harness、验证器、真实资源账本及闭环后果都被单独审计。

## 本月趋势总览

### 智能体安全控制下沉到执行层

安全边界从识别恶意文本转向追踪来源、用户授权、参数证据和数据去向，并在工具执行前做放行判断。委派、历史复用和上下文重建会抬升低权限内容的角色，来源元数据必须跨全链路保留。

依据：When Context Gets Root 覆盖六个框架、十三类目标并全部找到攻击路径；SARA 在 8730 个攻击实例上把 ASR 降至 0.06%—0.63%，但 token 增至无防御的 1.91—2.21 倍。现有结果仍依赖固定攻击模板、人工策略或模型判断，尚未经过自适应攻击和开放工具生态验证。

### 记忆竞争点转向正确使用和边界治理

更长上下文和更大检索容量不能解决回复不用证据、事件被拆散、约束过期及恶意内容写回的问题。值得长期跟踪的是事件级检索、时态更新、安全规则硬通道和记忆隔离，而不是单纯扩容。

依据：MemUse 的四个月部署中，增加长上下文或 RAG 容量未提高满意度，两阶段抽取后仍有 77% 的回复没有引用检索细节。压缩断崖、失效约束和技能库自投毒目前主要来自受控实验，生产环境发生率仍缺数据。

### 评测单位变成执行证据和完整交付

代码、科研、安全和控制任务开始分别核验输出、执行过程、交付物与实际后果，单一最终分数越来越不足以证明任务完成。下一步瓶颈是验证器覆盖率、拒绝分支是否真实生效，以及 LLM 裁判的同源偏差。

依据：SWE Refactor Bench 的 520 次运行中仅 28 次通过全部验证；PLCBench 的 240 轮里有 137 轮写到过程对象，但只有 75 轮维持目标。严格验证显著压低表面成功率，但任务规模、隐藏测试和规则评分器仍可能遗漏作者未预见的失败。

### Harness 成为可优化的软件层

提示词、工具 schema、状态表示、上下文裁剪、完成检查和确定性技能开始被整体搜索与修改。同模型换 harness 可产生两位数的结果差异，但系统增益必须与更多 token、调用次数和墙钟时间分开核算。

依据：Same Model, Different Harness 在 20480 token 窗口下把 SWE-bench Verified 完整解从 43 提到 72；同时提示 token 从 37.8M 增至 80.7M，墙钟时间从 1.3 小时增至 4.6 小时。当前证据支持 harness 影响显著，不支持其已经实现等算力效率提升。

### 系统优化开始核对真实资源账本

KV 淘汰、前缀复用、优化器和机密计算不再只比较理论压缩率或算子速度，而是核对物理显存、通信、额外评分计算和端到端吞吐。结构性复用和非均匀资源分配值得跟踪，但底层存储布局与额外计算可能逆转表面排名。

依据：Trust the Mass 发现部分 KV 结果依赖未释放物理显存或提前看到问题，ContourKV 重构评分成本达到稠密 prefill 的 8.7—13.6 倍。SAMuon-lite 在 124M 到 1B 配置中报告节省约 13.3%—22.1% token，但只有单种子、统一 12 层结构和单一数据源。

### 闭环后果进入智能体与控制评测

机器人、游戏和工业控制开始检查推理延迟、已承诺动作、环境反馈及持续状态变化，而不是把单步动作或工具写入当作成功。慢速高层推理与高速控制解耦、长预测短执行和局部意图表示构成可持续的方法路线。

依据：Act with Intent 在模拟和真实机器人任务上报告提升，但新增表示使推理延迟增加约 10%—21%，且结果受教师和单个任务影响。PLCBench 中短暂异常到持续 30 秒影响存在明显漏斗，说明接口访问能力不能直接外推为真实物理风险。

## 本月主要研究主题

### 来源、授权与数据流

本月最密集的安全信号是把文本内容、消息角色和执行权限分开建模，并在上下文重建、参数绑定、工具执行和外部输出处保留来源。模型拒答不是稳定边界，摄取、记忆写回和 harness 重放都可能绕过它。

- 外部数据可以支持参数取值，但不能扩大动作类型、目标、接收方或权限范围。
- 委派、定时任务、持久目标和子智能体会重标消息角色，来源元数据不能只留在原会话。
- Office 文档、记忆和技能库表明摄取与写回链路需要独立审计。
- 安全率必须与正常任务完成率、额外 token 和误杀率同时报告。

### 长期记忆与上下文治理

容量不足不是当前唯一瓶颈，检索单位、生成阶段是否用证据、约束时效和压缩边界更关键。长期路线是事件化索引、时态冲突处理、安全规则硬保留和自动写回隔离。

- Direct QA 高分不能预测自然对话是否主动使用旧信息。
- 固定文本块会拆散共同生效的规则、例外和事件证据。
- 安全规则与普通事实共同摘要会产生压缩断崖。
- 英语训练的压缩策略对中文等非英语内容可能系统性过删。

### 可执行评测与证据链

最终答案正在被拆成任务合同、执行轨迹、交付物和持续后果，以区分真实完成与评分漏洞。验证器自身成为新的薄弱环节，需要差分测试、mutation testing 和人工抽查。

- 代码迁移必须同时验证实现替换和行为保持。
- 安全评测需要区分工具调用、短暂异常和持续物理影响。
- 规则评分器只能覆盖作者预先枚举的失败，LLM 裁判又可能引入同源偏差。
- 知识编辑等基准缺少真实负例时，路由和拒绝能力无法测量。

### Harness、接口与工作流

Agent 外壳已成为独立软件层，工具 schema、结构化状态、上下文裁剪和完成检查都能改变结果。同模型比较若不固定 harness、调用预算和验证器，难以归因基础模型能力。

- 紧上下文下，工具结果裁剪和失败检测可显著提高完成率。
- 结构化动作与确定性计算适合依赖明确的任务，但可能混入人工领域知识。
- 自动搜索 harness 的收益需要与简单重试、模板路由和人工修补对照。
- 固定选择集反复用于搜索会形成反馈泄漏和过拟合。

### 真实资源账本

系统和训练优化开始按实际显存、吞吐、通信、额外评分计算和失败回退核账，而不是只报逻辑压缩率或局部算子速度。利用注意力、梯度谱和前缀中的非均匀性是稳定方法路线，但兑现收益依赖底层实现。

- KV 容量下降必须对应物理显存释放和可用存储布局。
- 问题提前可见、重构评分和跨卡通信会改变方法排名。
- 优化器 token 节省需要多种子、不同深度和不同数据配方复验。
- 机密计算方案必须报告真实 TEE 延迟、内存流量和端到端吞吐。

### 闭环控制与真实后果

动作正确不等于任务完成，策略需要在推理延迟、旧动作承诺、环境反馈和误差累积下保持稳定。局部意图、异步状态补齐和长预测短执行值得长期跟踪，当前证据仍集中在少量平台和受控环境。

- VLA 开始显式表示动作块服务的局部目标和未来状态。
- 慢速高层推理需要与高速执行器解耦。
- PLC 写入和短暂异常不能替代独立过程轨迹中的持续影响。
- 真实机器人与工业控制结果缺少多平台、随机延迟、传感器噪声和不可逆副作用验证。

## 与上一期月报相比的变化

- 没有上一期月报，本期作为比较基线；资料只有 2026-W35，不能判断方向相对上月是否真正升温或降温。
- 基线重心落在智能体外围系统，而非基础模型规模：来源与授权、记忆使用、harness、验证器和闭环后果构成主要研究对象。
- 基线评测标准从最终答案扩展到执行轨迹、实现语义、完整交付和物理影响，验证器与 LLM 裁判也被纳入审计。
- 基线系统标准要求报告物理显存、额外 token、墙钟时间、通信和回退成本，不接受只用压缩率或局部加速证明收益。
- 现有材料不足以把自动 harness 搜索、多智能体或自我改进判定为成熟趋势；多数增益尚未与等算力重试、人工修补和固定模板充分拆分。
- 短期热度目前无法可靠识别；知识编辑 scope 负例和 OOXML 解析差异值得关注，但是否形成连续路线需看后续月份是否出现独立复现与防御工作。

## 阅读建议

- 开发者：优先把来源、授权和参数证据做成工具执行层的强制字段，并让记忆、日志和委派链完整保留这些元数据。评估改动时同时记录成功率、误杀率、token、墙钟时间、物理显存和回退成本，避免把更多预算包装成算法增益。
- 研究者：优先补真实负例、自适应攻击、多随机种子和跨平台复现，并把验证器与 harness 作为实验变量公开。月内证据最支持来源授权、记忆治理、可执行评测和真实资源核算，自动 harness 搜索及特定基准负结果仍需连续月份确认。
- 技术负责人：选型时不要只看模型名和最终平均分，应审计 harness 配置、工具权限、记忆写回、验证器覆盖率及端到端资源账本。涉及机器人、PLC、文档摄取或机密计算时，把持续物理后果、解析差异和真实硬件开销列为上线门槛。
