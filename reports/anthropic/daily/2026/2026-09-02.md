### Building commerce agents with Claude
- 链接：[https://claude.com/blog/claude-for-commerce-agents](https://claude.com/blog/claude-for-commerce-agents)
- 发布时间：2026-09-02
- 类型：产品公告与智能体
- 摘要：Anthropic 发布一套可直接 fork 的商业智能体蓝图，包含面向消费者的购物智能体和面向商家的运营智能体，并提供零售、旅行、电信和票务场景的参考实现。团队可以选择 Messages API、Claude Agent SDK 或 Claude Managed Agents（测试版）搭建，也可以用配套的 Claude Code 插件接入自有商品目录、政策和品牌规则。蓝图还包含价格与库存校验、操作权限限制和人工审批等安全措施。
- 关注点：这套蓝图把商业智能体从示例推进到可改造的工程起点，同时保留企业现有的结账、支付和业务系统。对准备上线购物或商家运营智能体的团队，参考实现、行业样例和安全约束能省去一部分脚手架与方案摸索。

### A guide to the anatomy of effective commerce agents
- 链接：[https://claude.com/blog/the-anatomy-of-effective-commerce-agents](https://claude.com/blog/the-anatomy-of-effective-commerce-agents)
- 发布时间：2026-09-02
- 类型：智能体工程
- 摘要：文章总结了 Anthropic 与零售、平台、旅行、娱乐和电信团队共建商业智能体的工程经验。推荐的核心架构是单模型智能体循环，配合 skills、业务工具和 eval，而不是按业务领域拆成多个 subagent；高频规则放进 system prompt，长尾流程交给 skills。文章还覆盖工具边界、三层记忆、提示缓存、模型选择、延迟与成本，以及把权限、审批和策略执行放在 harness 中。
- 关注点：文中的做法不只适用于商业场景。它给出了较完整的生产智能体检查表：复用现有业务系统、控制上下文规模、用 eval 管理非确定性，并在模型之外强制执行安全规则。团队可以据此审视现有 agent 架构是否引入了不必要的多智能体切换、延迟和状态损失。
