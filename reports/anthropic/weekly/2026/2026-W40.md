# Anthropic 官方动态周报（2026-W40）

## 本期最重要的信号

本期最明确的变化，是 Claude 的集成生态开始配套更完整的发现、发布和采购流程。9 月 23 日的 Claude Marketplace 汇集插件、连接器、agent 产品和服务伙伴，9 月 25 日的开发者门户补上提交、校验、审核和使用数据。相比上一期把聊天、任务执行和成果编辑整合起来，本期进一步回答了用户去哪里找工具、开发者如何发布，以及企业如何采购的问题。

工程内容则集中在长任务的成本与验收：两篇 Opus 5.5 文章解释缓存和交互轮数如何影响费用，代码现代化指南要求提前定义可验证的验收条件。科研案例展示了持续执行的可能性，也保留了明确边界：ART 系统的主要功能尚未确定，九圈计算沿用已有方法。它们支持对具体研究流程的讨论，尚不足以推出普遍的科学发现能力结论。

以下依据窗口内已有的 7 份日报、11 条官方内容。9 月 28 日的新增条目仅有列表页标题，保留在来源明细中，不据此扩展分析。

## 插件生态：统一入口之外，发布与采购流程也在补齐

9 月 23 日，Claude Marketplace 将插件与连接器、agent 与产品、咨询和系统集成服务汇集到同一入口。官方称已有超过 2,000 个插件和连接器，合作伙伴可通过 MCP 和 Agent Skills 构建集成，申请上架产品或加入 Claude Partner Network。[官方发布](https://claude.com/blog/claude-marketplace)

9 月 25 日开放的插件提交门户面向付费方案开发者，支持远程 MCP 连接器，以及托管在 GitHub、包含 MCP 服务和 Agent Skills 的插件包。门户提供自动校验、安全扫描、审核反馈、发布控制及上线后的安装和发现数据。统一 Claude 与 Claude Code 的插件发现体验仍是后续计划，已有目录内容暂时无需调整。[开发者说明](https://claude.com/blog/build-plugins-for-claude)

同周的 CodeRabbit、Power Digital、ThoughtSpot 案例介绍了将部分 Anthropic 合约承诺支出用于 Vercel、Snowflake 等伙伴产品的做法。这类安排仍处于有限预览，不能将集中展示产品理解为所有企业都能用现有合约采购。[官方案例](https://claude.com/blog/how-coderabbit-power-digital-and-thoughtspot-scale-with-snowflake-and-vercel-on-claude-marketplace)

与上一期 Salesforce 插件和小企业工作流的单项扩展相比，本期更关注这些集成如何被找到、审核和采用。对开发者，新增的是明确的发布流程和使用反馈；对企业，首先要核对插件适用范围、采购资格与合约条款。现有案例没有提供足以推断普遍采购效率收益的数据。

## 编码工程：成本要按任务衡量，正确性要提前约定

9 月 22 日和 24 日的两篇文章围绕同一成本变化展开：官方称 Opus 5.5 的 API 输入、输出单价较 Opus 5 降低 20%，缓存读取单价降低 60%；Claude Code 也改善了缓存复用。官方汇总数据显示，近半年每次请求的上下文增长了 2.6 倍，解释了为何缓存读取对长编码任务费用更重要。[任务成本拆解](https://claude.com/blog/what-a-task-costs-on-opus-5-5)、[长会话成本说明](https://claude.com/blog/claude-opus-5-5-built-for-coding-sessions-that-use-more-context)

两篇材料应合并理解为一组成本说明。实际总费用还取决于交互轮数、缓存命中、输出 token（含思考）和重试次数，不能把单价降幅直接当作任务节省比例。9 月 22 日的示例未计入缓存写入，也不能直接对应实际账单。开发团队可用 `/usage` 比较同一任务的完成轮数、输出量和估算费用，再决定模型与 effort 设置。

9 月 23 日的代码现代化指南把关注点延伸到整个交付流程：先明确目标、可自动验证的验收条件、上线规则和环境审批，再构建 agent 工作流，由小范围试点逐步扩展。文章区分同技术栈升级、保持行为不变的跨栈重写和改变行为的重新设计。[官方指南](https://claude.com/blog/how-to-prepare-for-ai-driven-code-modernization-projects)

这为上一期 Projects 并行协调能力补充了实践条件：任务能被拆分和持续执行之后，团队仍需提供判断结果是否正确的证据，以及足够的评审和发布能力。基于本期材料，试点应同时记录 token 用量、重试率和人工评审负担，避免只按代码生成速度判断项目进展。

## 委托与协作：既要理解偏好，也要明确数据可见范围

9 月 24 日的 Project Swap 让六个办公室的 201 名员工各带一本书，由 agent 根据简短访谈交换图书。agent 对成对图书的偏好判断与参与者一致的比例为 61%；交易结果与理想分配的差距主要来自偏好理解不准，模型选择对谈判结果的影响也大于指令差异。这是受控的内部图书交换实验，不能直接外推至一般市场。[官方研究](https://www.anthropic.com/research/project-swap)

同日的 Claude Tag 更新允许用户在 Slack 频道调用自己的个人连接器，且只能由本人发起。回复可先审核再发布，或由自动模式筛查敏感内容；定时任务和 Claude 自主发起的操作仍使用管理员配置的频道连接器。功能正向 Team 推出，Enterprise 随后跟进。[官方发布](https://claude.com/blog/claude-tag-now-supports-personal-connectors-in-channels)

两项内容分别处理委托中的意图理解和协作中的访问权限。Project Swap 提醒使用者用样例决策检查 agent 是否理解偏好；Claude Tag 则要求区分“本人能读取的数据”和“可以向频道成员展示的回复”。它们延续上一期的授权主题，但不能合并视为一种安全机制。

## 科研实践：持续计算与实验验证构成两类证据

9 月 23 日，Anthropic 介绍新设的生命科学研究团队和实验室，并公布 Claude 发现的阵列关联逆转录酶系统（ART）。约 950 个 agent 在 21 小时内搜索 DNA 数据，识别逆转录酶附近的重复序列和辅助蛋白；人类科学家随后通过实验确认，重复阵列可表达为不同的短 RNA。ART 的主要功能仍未确定，类似 CRISPR 的重复结构也不等于已证实的可编程基因编辑能力。[官方公告](https://www.anthropic.com/news/claude-discovers-novel-enzyme-system)

9 月 25 日的受邀文章介绍了另一类科研工作：Fable 5.1 在 Claude Science 中沿两条已有计算路线完成平面 N=4 超杨–米尔斯理论的九圈六粒子散射振幅计算，结果经 Lance Dixon 核验。每条路线的终端用户成本约为 1,000–2,000 美元，研究人员主要通过继续工作的指令维持任务运行。作者强调成果依赖已有方法，研究对象也是理想化理论。[研究文章](https://www.anthropic.com/research/yes-claude-can-do-nine-loops)

相比上一期生物模型提速与生命科学准入安排，本期增加了数据库筛选后接实验验证，以及持续编程计算后接专家核验的案例。值得继续观察的是结果如何复现、人工验证承担哪些工作，以及持续运行的实际成本；这两项案例本身并未解决所有这些问题。
