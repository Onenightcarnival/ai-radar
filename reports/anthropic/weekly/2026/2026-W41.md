# Anthropic 官方动态周报（2026-W41）

## 本期最重要的信号

本期最集中的变化，是围绕 agent 的定制、管理和企业交付补充具体做法。9 月 29 日的 Asana 案例区分任务执行权限与长期记忆修改权限；10 月 1 日的 Claude Code mods 将定制范围扩展到工具调用、权限请求和界面，同时明确本机访问权限；10 月 2 日的 Frontier Academy 则把用例选择、安全审查和交付纳入工程师培养。相比上一期 Marketplace 的发现、发布与采购流程，本期更关注工具进入组织后由谁管理、如何纠正，以及谁来完成部署。

研究内容提供了另一条共同提醒：能力、实际效果和采用条件需要分别判断。机器人能执行的任务不等于经济上值得自动化的任务，隔离环境中的漏洞利用成绩不等于真实攻击成功率，科学计算正确也不自动意味着研究有价值。以下基于本期已有的 7 份日报、11 条官方内容，日报窗口覆盖完整。

## Agent 定制走得更深，权限与长期行为需要分开管理

9 月 29 日，Asana 介绍 Claude 驱动的 AI teammates 如何进入 Work Graph：接收任务、发送消息并留下工作记录。每个 agent 有明确角色、技能和权限，实际访问范围还受触发者权限约束。团队成员可以反馈，但只有管理员和编辑者能把反馈写入长期共享记忆，或撤销、删除记忆。[官方案例](https://claude.com/blog/agents-you-can-coach-how-asana-builds-human-agent-teams-with-claude)

这延续了上一期 Claude Tag 的授权主题，又增加了多人共享 agent 的管理问题：允许某人发起任务，不等于允许其改变整个团队之后使用的行为规则。任务记录与记忆修改权分开，有助于追溯 agent 为什么这样执行，以及由谁负责修正。

10 月 1 日发布的 Claude Code mods 允许开发者用 TypeScript 函数在事件前后运行代码或替换事件，修改提示词、拦截工具调用、处理权限请求，也可添加界面和替换内置功能。Mods 随插件分发，支持 CLI 和桌面端，并可热加载。[官方发布](https://claude.com/blog/claude-code-mods)

与上一期插件门户相比，这次变化涉及执行过程本身。日报明确指出，mods 不在沙箱中运行，具有与 Claude Code 相同的本机访问权限；Team、Enterprise 和受管理设备默认优先加载 sec-default，限制用户 mods 覆盖拒绝规则等行为。因此，团队评审插件时需要把代码来源、加载顺序和权限规则一起考虑，不能仅凭插件能够安装就判断它适合共享部署。Asana 与 mods 处理的是不同层次的控制问题，不应视为同一套安全机制。

10 月 5 日的 Cresta 案例进一步展示行业经验如何进入 agent 开发工具。Conductor 以 Claude Agent SDK 处理上下文、工具调用和代码执行，将业务规则、开发经验及评测方法保存为共享技能，并从产物、执行路径、质量和资源消耗四方面评测，在更换模型或框架时复用同一套任务。Cresta 称其自身及伙伴早期用例的首次部署时间缩短约一半；这仍是特定案例结果。相比只扩展工具接口，这一实践更值得关注的是如何保留关键业务流程的确定性约束和人工介入，以及如何持续验证改动。[官方案例](https://claude.com/blog/how-cresta-turned-cx-expertise-into-an-agent-builder-on-the-claude-agent-sdk)

## 企业采用：业务流程、预算审计与交付人员同时推进

9 月 30 日，Anthropic 销售团队介绍基于测试版 Claude Managed Agents 的购买咨询 agent：回答价格、安全和数据问题，推荐套餐并引导结账，复杂需求携完整对话转交销售人员。官方称其每天处理数千次对话，转交客户形成销售机会的比例超过旧表单线索的两倍，成交约快五天。这些是 Anthropic 自身业务数据，不能直接作为其他企业的预期收益。[官方实践](https://claude.com/blog/how-anthropics-sales-team-rebuilt-inbound-with-claude-managed-agents)

这篇案例更可借鉴的部分是运营方法：业务人员参与提示词修改，变更经过预发布测试并支持回退，转人工原因用于后续改进，客户也可自行选择 agent 或销售代表。它把 agent 的持续维护放进了现有销售流程。

同日，Claude for Government 面向美国联邦和州政府机构正式开放，在获 FedRAMP High 授权的环境中提供编码和 agent 工作功能；Claude Code CLI 与 Claude for Microsoft 365 则处于早期访问。平台按固定额度购买用量，设置支出硬上限，支持分部门管理、身份集成和审计日志。机构仍需完成自身的 ATO 授权流程，不能把平台授权等同于机构部署已经获批。[官方发布](https://claude.com/blog/claude-for-government-is-now-generally-available)

10 月 1 日的巴克莱案例补充了企业扩展的现状：内部知识助手已有逾 1.6 万名员工采用，全球市场业务邮件平台每天处理约 12 万封邮件；到 2026 年底让 50% 开发者使用 Claude Code 仍是计划目标。采用人数、处理量与未来覆盖率需要分开看，它们本身也不是生产率提升的直接证明。[官方公告](https://www.anthropic.com/news/barclays-scales-claude)

10 月 2 日的 Claude Frontier Academy 承诺投入 1 亿美元，目标是在 2027 年底前培养 1 万名 Frontier Deployed Engineers。首个项目结合数天线下模拟部署训练与通过考核后的 12 周企业内实战；学员需带着所在企业的 Claude 项目参加，首批认证预计于 2027 年初发放。[官方公告](https://www.anthropic.com/news/claude-frontier-academy)

这些材料共同说明，本期官方内容持续强调部署所需的组织条件：业务团队能维护工作流，管理者能控制预算和访问，工程师能完成安全审查与交付。与上一期采购入口扩展相比，关注点进一步转向采用后的执行能力；培训人数和开发者覆盖目标尚不能算作已交付成果。

## 安全与经济研究：先分清测量对象，再讨论影响

9 月 29 日的 GLM-5.3 研究将网络攻击能力与防滥用机制分开评估。Anthropic 报告，在隔离环境的 ExploitBench 中，GLM-5.3 在 410 次尝试中成功 50 次，Claude Mythos Preview 为 56 次；在另一组模拟恶意请求测试中，GLM-5.3 在不同绕过条件下的响应比例为 64% 至 100%，受安全机制保护的 Claude 未执行有害任务。[官方研究](https://www.anthropic.com/research/glm-5-3-and-the-spread-of-advanced-cyber-capabilities)

这些结果来自 Anthropic 的特定基准和模拟条件，不能外推为真实攻击成功率或所有情境下的安全保证。文章提出扩大防守方访问与加强独立评测的主张；对技术管理者，更直接的启示是分别评估模型能做什么，以及部署中的限制是否有效。

9 月 30 日的机器人任务暴露指数同样强调条件差异。研究使用 Claude 与 O*NET 任务数据，估计现有机器人在特定条件下可执行约 74% 的体力工作任务，覆盖美国总工作时间的 34%，但多数需要受控环境；按成本衡量，仅 0.3% 的工作任务使用机器人比人工更划算。任务占比按工作时间加权，不能理解为岗位替代比例。[官方研究](https://www.anthropic.com/research/what-work-can-robots-do)

9 月 29 日启动的新一轮 Anthropic Interviewer 则收集用户的正负面 AI 经历及对开发公司的期待，并首次允许参与者自愿公开完整访谈供外部研究者分析。研究计划持续至 10 月 6 日，本期材料只是招募与方法说明，没有结果；Claude 用户与自愿公开访谈者也不代表全体公众。[官方说明](https://www.anthropic.com/research/your-thoughts-on-ai)

相比上一期 Project Swap 的受控偏好实验，本期经济与社会影响材料扩展到任务自动化条件和用户经历收集。现有证据支持讨论研究方法与采用约束，尚不足以判断宏观就业或公众态度已经发生何种变化。

## 科研实践：从完成计算延伸到选择可验证的问题

10 月 1 日，Matthew Schwartz 的客座文章介绍科学计算工具集 BootLoops：整合代码与数学方法，寻找适合现有 Claude 能力的可验证计算问题，再由领域专家判断研究价值。文章涉及散射振幅、生态学和群体遗传学，也介绍多会话协调、文件记录与独立复核。[研究文章](https://www.anthropic.com/research/claude-shaped-science)

上一期九圈计算关注持续执行已有计算路线，本期进一步讨论如何选择问题和组织验证。需要保留两条边界：BootLoops 由 Schwartz 个人拥有和维护，并非 Anthropic 项目；部分成果仍在探索与验证中。对科研使用者，选题、解释和独立复核仍是工作的一部分，不能仅凭计算顺利完成判断科学贡献。
